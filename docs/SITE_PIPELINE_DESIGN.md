# 每站接入与六步加工流水线设计

状态：历史设计稿，包含尚未实现的后续设想。0.16.19 已接入六步客户端，当前实际行为、恢复边界和使用方法以 [SITE_PIPELINE.md](SITE_PIPELINE.md) 为准；下面的单一监控器、跨进程协调等不能当作已交付能力。

## 已确认问题与边界

本机 brometal.cn-25c3c387/code~q-d9fc91d45c09.html 文件头为 GIF87a，属于图片。采集模块旧版没有纠正带 .html 的资源名。SSM 的 scanner.WalkHTML 按 .html/.htm 扫描；htmlrewrite.LoadFile 对无声明且非 UTF-8 的文件拒绝解码。该文件符合失败条件；远端此次确切失败文件仍以 site_sync 审计中的 zr.results 为准。

上传前检查和打包时复查必须共用规则，不能上传伪 HTML；新采集以文件签名纠正类型及链接。旧模板保持原样，报告具体路径。目录同步和 ZR 注入是两个独立结果，不把 HTTP 400 当作未写入，也不能只因目录存在就标记成功。只读本地后台源码，不修改部署中的后台。

## 每个站点的顺序

识别站点 → 核对已有模板与断点 → 必要时校验/上传/同步/扫描 → 生成并固定该站点 TDK → TDK 全站替换 → 简繁抽样/全站转换 → 统计检测/清理 → 外链抽样/全站改写 → H1 抽样/全站注入 → 占位符抽样/全站注入 → 验收汇总。

已有站点只跳过创建；已有模板跳过上传，不能据此跳过尚未完成的六步。已有页面且本机无上传记录时，以远端 site_id、页面数及任务记录核对，禁止重新覆盖模板。所有六步都完成且输入指纹未变才跳过整个加工流程。这里没有发布步骤，处理工作副本后单独验收。

| 步骤 | 默认及输出 | 恢复方式 |
|---|---|---|
| TDK | TK=5、D=8；每站独立生成一组，持久保存 title/description/keywords，同站全部页面使用该组 | 重试复用原值，不重新随机生成；批次内碰撞检测，有限次重新生成 |
| 简繁 | 复用后台配置，当前截图为 s2t；抽样 20 页；skip_tdk=true | 记录配置版本与远端任务 ID；确认完成后不重跑 |
| 统计清理 | 先检测，全选安全可删项；混合脚本需复核项另列 | 0 命中视为正常完成，不重复提交空操作 |
| 外链 | 复用站点域名/协议，抽样 20 页后全站执行，不改图片/CSS等资源地址 | 保存规则摘要，未变配置和已完成任务跳过 |
| H1 | 默认 {{title}}；复用后台标记更新机制 | 已有系统 H1 更新/不变，不无限叠加 |
| 占位符 | 在系统 H1 后插入，依赖 H1 步骤完成 | 使用后台已有标记；不重复生成叠加块 |

抽样预览不等于全站验收。预览失败阻止该站此步骤；其他站继续。执行结果有失败数或需复核项不能标为全成功。随机 TDK 生成值与占位符的预览/正式执行差异必须显示在配置摘要中。

## 复用现有接口，避免另造页面改写器

已核对本地 SSM 源码：
- POST /api/tdk/lexicon/generate；POST /api/tdk/apply 支持 async。
- /api/convert/preview、/apply；/api/stat/detect、/clean。
- /api/link/preview、/apply；/api/h1/preview、/apply；/api/placeholder/preview、/apply。
- GET /api/tasks/:id、/progress、/items；POST /api/tasks/:id/cancel。
- /api/jobs 支持多站作业与 tdk_by_site，但 normalizeSteps 会重排为统计→简繁→外链→H1→占位符→ZR→TDK，并自动插入 ZR。

因此不能直接把用户的六步数组交给 /jobs 就声称按要求执行：H1 会早于新 TDK，得到旧标题。第一版复用各操作现有异步接口，通过统一阶段适配器保持用户顺序；后续若改后台，才在版本化接口中支持明确依赖顺序。不能为每个页面发一个 HTTP 请求。

## 分层

- View：输入、勾选、虚拟表格、合并进度、预览及汇总。无网络请求、打包或数据库循环。
- Application Controller：创建计划、提交/恢复/取消；调度器复用有界并发。
- Domain Plan/Stage：声明步骤、依赖、配置指纹、验收条件，纯模型可测试。
- Stage Adapter：TDK/转换/检测等参数与响应映射，调用统一 SiteClient；不自己建立会话。
- Repository：SQLite 事务保存 site_id、template_digest、config_hash、阶段、task_id、结果、TDK原值。
- SiteClient/TaskMonitor：统一登录、限流、超时、错误分类及批量轮询；全应用共享请求额度。
- SSM：实际全站文件改写、备份和站点锁；客户端不重复实现这六套改写逻辑。

## 状态与恢复

阶段：pending → previewing → ready → submitting → running → succeeded / failed / uncertain / review_required / cancelled。

执行前事务写入 submitting，再发请求；收到 task_id 立即保存。断线但有 task_id：查询同一任务，禁止重复提交。提交响应丢失且无 task_id：通过远端任务列表按站点/类型/时间核对；无法唯一确认则 uncertain，不能靠超时后盲重试来“自愈”。后台当前缺少可靠幂等键，不声称能保证跨断线 exactly-once。

幂等标识包含账户、site_id、模板版本、步骤和配置摘要。用户重启客户端后恢复监控；失败仅影响本站后续依赖步骤。网络 GET 可有限次退避；上传/同步/改写 POST 无已核实结果不自动重放。删除或换模板必须核对远端工作目录及绑定；有已上传内容时不能只释放本机记录。

## 吞吐和进度

域名一入队即显示；准备完成一个就更新一个。预览仅校验本次候选模板，跳过已占用路径、已完成站点，已上传恢复不再扫描本地库。模板读取块为 1 MB，扫描/校验进度约 200 ms 合并一次。上传限一条通道，其余 API 可按站点并发 1–4 处理；同站步骤严格串行。

远端长任务使用 async=true 返回 task_id 后释放提交线程，由一个 TaskMonitor 定时查询活动任务；不为每页/每文件创建线程。站点列表每批读取一次建立索引，不能每步拉全站点列表；上传前对目标站必要复核保留。任务明细按需分页，普通进度只取计数和当前阶段。页面统计结束时汇总一次，避免 UI 逐文件刷新和 N+1 HTTP 查询。

## 验收用例

1. 100 个模板、1 个新域名，仅校验必要候选模板；第一个域名结果早于后面域名校验结束显示。
2. GIF/PNG/PDF/ZIP 冒充 HTML 被上传前拦截；正确编码真实 HTML 保持原内容。
3. 已存在空站点不重复创建；已有模板不重复上传；六步未完成的仍进入处理队列。
4. 第一个站点失败不阻断第二个站点；断电后有 task_id 仅恢复轮询。
5. 各站 TDK 不同；同一站重试 TDK 不变；H1 使用更新后的 title。
6. 统计0命中、无变化、需复核、部分失败分别计数，不能把请求200直接视作全站完成。
7. 重复点击和并发客户端争用不能绕开本地状态和后台站点锁；配置变化后只失效受影响步骤。

交付顺序：先发布当前性能与预检修复，再按上述适配器/持久状态/监控器接入六步，使用模拟后台验证，再做真实后台的小批量验收。此文档不代表已在真实站点执行过改写。
