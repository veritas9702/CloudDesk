# 未发布站点填充、域名复制与一次重建（0.16.20）

## 列表

加载站点列表时，后台并发核对 `/api/publish/versions?site_id=...`，页面逐步显示状态。当前接口没有批量发布字段，客户端限制两路查询并复用全局后台限流，不把站点启用状态、页面数或本机模板完成状态当作发布状态。

当前发布版本有效表示已发布；无当前版本且无发布历史表示未发布。有历史但没有当前版本、响应不完整、查询失败都标记待核实，不自动填入。“未发布”不包含已发布站点的待发布修改，也不证明站点实际可访问。

默认自动填入已核实未发布的主域名：仅更新空输入或上次自动填充且没有手工修改的输入。也可点击“填入未发布”主动替换。导入时保留每站编码、名称、协议和泛域名配置；不会因全局默认设置不同而把已有站点视为新站。

“复制全部域名”使用成功加载的完整分页列表，包含所有发布状态；去掉 `*.`、规范大小写和尾点、去重，一行一个，不附带协议和路径。保留 `www` 等真实子域名。无效主域名跳过并报告数量；账户切换清空缓存。

## 自动重建一次

勾选六步加工，选择有备用模板的父目录，再勾选“失败自动重建一次”。执行确认会明确说明删除失败站点及其远端目录。原有失败可从结果汇总点击“失败站点换模板重建一次（先预览）”，核对原 ID、域名与替换目录后执行。

处理顺序：

1. 核实站点、发布版本和本机重建次数。已发布或状态不明的站点不自动删除，报告人工处理。
2. 选择其他未使用、未隔离的本地模板。检查伪 HTML、链接路径、文件/体积限制，逐 HTML 检查真实 body 标签；实际压缩验证 300 MB 限制。
3. 执行前再次校验并打包替换模板，预留该模板，防止被别的流程占用。此时尚未删除原站点。
4. 复核原 ID/域名/设置未变、仍未发布；持久登记一次重建机会，使用后台带 confirm_code 的删除接口。
5. 再读后台确认原 ID/编码消失，才解除原本机绑定、隔离旧模板、清除原六步断点。保留原始 TDK 与审计记录。
6. 创建新站 → 上传备用模板 → 同步 → 扫描 → TDK → 简繁 → 统计清理 → 外链 → H1 → 占位符。复用原上传适配器、六步适配器和按域名隔离的审计执行器。

第二次失败保留具体后台任务号、文件原因和审计，可导出汇总；不会再自动删除重建。次数按本机账户/站点编码持久保存，重启不重置。删除响应不确定、预留模板或站点变化、缺少备用模板等情况停止报告，不盲目重复删除。删除前预检失败不会消耗重建次数。提交删除后中断需要人工核实，当前版本不自动推断删除结果。

原失败模板的本地文件不直接删除，但被隔离，普通自动分配和重建均跳过；新采集或人工修复应保存为新的模板。此版本未提供解除隔离按钮。

此功能修改真实后台的站点时会删除其远端目录。客户端没有新增发布操作；原 TDK 固定不重新生成。所有验证使用模拟后台，没有对真实后台进行删除、重建或发布。
