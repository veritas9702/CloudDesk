# TDK 优先的六步加工与发布（0.16.24）

客户端已接入，使用本地 SSM 源码核对接口与离线模拟后台验证。没有在真实后台执行改写，六步成功后异步发布上线。

## 使用

批量建站页填写域名，勾选“TDK → 转换 → 清理 → 外链 → H1 → 占位符 → 发布”。新站还需勾选上传模板并选择目录；已有模板只加工，不重复上传。也可从站点列表选中已有页面的站点，点击“加工并发布”。

点击“登录并预览”时，先逐站从后台词库生成 TDK（TK=5、D=8），检查同一账户标题不重复，事务保存分配。全部可处理站点分配完成后才生成执行计划。“核对 TDK”可以查看完整三项内容；预览不改站点页面。

确认执行后，同一站点依次处理：

1. 必要的上传、同步和扫描。已有模板不重传；同步/ZR 失败阻止本站后续加工。
2. TDK 全站替换：使用已保存的固定值，必须确认后台任务成功。
3. 简繁转换：抽样 20 页通过后全站转换，沿用后台词典，`skip_tdk=true`。
4. 统计清理：分页读取全部页面索引，每 100 页批量检测，仅选择安全可删片段所在文件；`include_review=false`。无安全命中正常跳过；需复核片段保留并报告。索引数与 TDK 文件数不一致时停止，避免漏处理。
5. 外链：抽样通过后全站改写，沿用站点域名及协议。
6. H1：抽样通过后全站注入，使用 `{{title}}`，依赖前面的新 TDK。
7. 占位符：H1 成功后抽样、全站注入，复用后台现有实现。

抽样仅检查部分页面；正式异步任务还需检查终态、失败数和待复核数，不能把 HTTP 200 当作全部完成。占位符正式生成的随机内容与抽样可能不同。

第七步发布：六步全部成功后校验工作副本摘要并异步发布上线。发布异常保留原任务，需核对线上版本。

## 断点与失败

本机 SQLite 持久保存账户、站点、模板/配置指纹、原始 TDK、阶段与后台 task_id。提交前先写 submitting，收到 ID 立即保存；成功步骤自动跳过。重新预览不会重新随机生成 TDK。

断网或关闭后，有 task_id 的步骤先查询原任务，不重复提交。没有 ID 的未知提交不会自动重试；在后台任务中心找到对应本次操作的 ID，使用“核对加工任务 ID”，客户端核对站点与类型后绑定，再预览继续。后台接口没有幂等键，不能仅凭同站点同类型证明请求完全相同，操作者仍需核对这次任务。

已确认失败的 TDK 可用同一固定值重新应用。其他加工步骤失败时只有在后台返回完整逐文件明细时，才重试失败文件，避免重复转换已成功页面。中断且明细不完整、只有待复核项、配置指纹变化等情况保留断点并提示核对；不能假装自动修复完成。重试范围保留到下一次提交，即使重试请求被拒绝也不会扩大为全站重跑。

一个站点失败停止本站依赖步骤，其余站点继续。结果汇总提供未完成六步重新预览入口。取消停止客户端调度和等待；已经提交的后台任务可能继续，ID 会保留，恢复后读取实际结果。

## 分层与调度

- `pipeline_store.py`：TDK 唯一分配与阶段事务，无 HTTP/Qt；标题唯一性使用索引。
- `pipeline_api.py`：六步接口参数、分页、抽样和检测映射，复用 SiteClient 的登录、会话、限流与超时。
- `pipeline.py`：依赖顺序、计划、恢复和任务终态校验；复用 TemplateWorkflow/TemplateSteps 以及审计执行器，不重写上传逻辑。
- `ui.py`：输入、预览、TDK 查看、合并进度与失败入口；耗时工作通过 WorkspaceJobs 执行，不阻塞 Qt 主线程。
- SSM：负责实际文件改写、备份与站点锁。客户端不另造六套 HTML 改写器。

站点间有界并发 1–4，同站串行。每个站点 worker 至多监控一个后台任务，取消感知轮询间隔 1.5 秒，最多等待 30 分钟后保留 ID；不会为每页开线程。站点列表每批读取一次，上传前保留必要目标校验；统计检测按批次而非逐文件请求。本次后台流程共用同一个 SiteClient 请求限流器。

不使用后台 `/api/jobs`：当前版本会把 TDK 排到 H1 之后并添加 ZR，违背本流程依赖顺序。客户端使用各步骤的 `async=true` 接口和 `/api/tasks/:id` 查询。

## 模板预检边界

0.16.18 已修正 GIF 等二进制被保存成 HTML 的采集问题；上传预检会拒绝旧模板中的伪 HTML，并给出文件路径。原始旧模板不自动改写。此项能阻止已识别的内容类型错误，不能保证服务器端磁盘、权限或所有 ZR 注入错误都不会发生。

如果在客户端以外更换工作目录、词典或规则，本机旧断点不能自动感知文件内容变化。应先核对原流程和后台结果，不绕过指纹保护强行重放。跨进程调度和服务端幂等键属于后续服务端能力，本版未实现。

0.16.23 预览性能：扫描复用目录项文件属性，逐文件响应取消并报告文件数/体积/当前文件。预览指纹缓存按相对路径、大小、修改时间、变更时间及文件标识核对，文件清单变化则重新计算；仅预览使用缓存，打包上传仍重新计算完整内容指纹并拒绝预览后变化。预览失败或取消显示未生成计划；完成前确认按钮保持禁用，完成后恢复。模板被其他模块清理时跳过已消失的候选，继续选择。

## 发布闭环（0.16.24）

六步检查点全部成功才调用 POST /api/publish/preview；该后台接口会补齐工作目录脚本，因此不在最初的计划预览调用。校验 diff 与 expect_digest 一致且文件数有效后，POST /api/publish/apply，携带 expect_digest 和 async=true；保存任务 ID，复用限流与轮询。摘要过期、脚本注入失败或无有效文件不会提交发布。

旧六步检查点保持兼容，只补发布；发布完成后跳过。发布失败或响应未知可能已经切换线上版本，保留原任务，仅核对，不自动重发或删站重建。无任务 ID 时使用核对加工任务 ID。需要在后台人工处理发布版本、电脑端页面或 Nginx 异常。预览及确认明确提示上线影响。
